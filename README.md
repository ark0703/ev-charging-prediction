# EV Charging Session Predictor

Predict how much energy an EV charging session will deliver (kWh) using a supervised scikit-learn model trained on realistic synthetic session data. The app includes a Python training pipeline, a FastAPI inference API, and a Next.js web UI for interactive predictions and model performance.

## What the model predicts

**Target:** `session_energy_kwh` — energy delivered during a single charging session.

**Features:**

| Feature | Type | Description |
| --- | --- | --- |
| `hour_of_day` | 0–23 | Local hour when charging starts |
| `day_of_week` | 0–6 | Monday = 0 |
| `station_id` | categorical | `downtown`, `airport`, `highway`, `suburban`, `mall` |
| `charger_type` | categorical | `level2` (11 kW) or `dc_fast` (150 kW) |
| `vehicle_battery_kwh` | numeric | Pack size (45–100 kWh in training data) |
| `starting_soc_pct` | numeric | State of charge at plug-in |
| `ambient_temp_c` | numeric | Ambient temperature (affects thermal efficiency) |
| `station_occupancy_pct` | numeric | Share of stalls in use |

## Synthetic data assumptions

Data is generated by `ml/generate_data.py` with plausible patterns:

- Commute peaks (8:00 and 18:00) and weekend uplift increase session energy.
- Airport and downtown stations skew higher than suburban sites.
- DC fast sessions often deliver more energy per visit; Level 2 sessions reflect shorter dwell times.
- Lower starting SOC and larger battery packs increase delivered energy.
- Cold and very hot weather reduce effective delivery slightly.
- Higher station occupancy adds mild congestion noise.

Schema is written to `ml/data/charging_sessions.csv` (gitignored; regenerated by training).

## Model & metrics

- **Algorithm:** `GradientBoostingRegressor` with standardized numeric features and one-hot encoded categoricals.
- **Split:** 80/20 train/test, `random_state=42`.
- Metrics are saved to `models/metrics.json` after training (RMSE, MAE, R² on the held-out test set).

## Quick start

### 1. Install dependencies

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
npm install
```

### 2. Train the model

```bash
npm run train
# or: bash scripts/train.sh
```

This generates synthetic data, trains the model, and writes:

- `models/model.joblib`
- `models/metrics.json`

### 3. Run the app

```bash
npm run dev
```

This starts:

- **FastAPI** inference API on `http://127.0.0.1:8765`
- **Next.js** UI on `http://127.0.0.1:4321` (proxies `/api/ml/*` to the Python API)

Open the UI, enter session features, and view predictions plus model metrics and recent in-session predictions.

## Project layout

```
api/main.py              FastAPI inference service
ml/generate_data.py      Synthetic session generator
ml/train.py              Training script (train/test split + metrics)
models/                  Saved model.joblib + metrics.json
scripts/train.sh         End-to-end training pipeline
scripts/dev.sh           Start API + web together
src/                     Next.js + shadcn/ui frontend
```

## Manual API usage

```bash
source .venv/bin/activate
uvicorn api.main:app --host 127.0.0.1 --port 8765
```

```bash
curl -X POST http://127.0.0.1:8765/predict \
  -H 'Content-Type: application/json' \
  -d '{
    "hour_of_day": 18,
    "day_of_week": 2,
    "station_id": "airport",
    "charger_type": "dc_fast",
    "vehicle_battery_kwh": 82,
    "starting_soc_pct": 28,
    "ambient_temp_c": 12,
    "station_occupancy_pct": 64
  }'
```
